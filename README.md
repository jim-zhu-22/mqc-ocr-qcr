# MQC-OCR-QCR

将PDF/图像质量控制单转换为逐页OCR、章节、结构化规则、IR/DSL，再对JSON物料执行必要性、完整性、准确性、唯一性评分。每个阶段及每次评分均保存JSON，可在本地Demo查找、预览、下载和沿规则追溯原文页图。

这是本地可审查开发仓库。`0.0.0.dev0` 仅为安装包开发标识，**不是已发布正式版本**。尚无公开远程仓库、发行许可证或真实服务验收结果。授权状态见 [LICENSE_STATUS.md](LICENSE_STATUS.md)。

## 安装与启动

需要 Python 3.11+；本次验证平台为 Windows / Python 3.13.9。PowerShell：

```powershell
cd <本仓库目录>
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\.venv\Scripts\python.exe -m pip install --no-deps .
.\.venv\Scripts\python.exe -m mqc_qcr --port 8765 --data-dir runtime
```

打开 <http://127.0.0.1:8765>。无需数据库、Node构建、向量服务或外部OCR程序。PDF通过PyMuPDF渲染；输入限制30MB、100页、图像4000万像素。仅绑定本机回环接口，不提供多人生产部署。

开发与测试：

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[test]"
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe scripts/reproduce.py
```

Linux/macOS可使用 `.venv/bin/python` 替代对应路径；本次未进行这些系统上的安装验收。

## Demo界面

界面以用户指定的 `代码整合/demo/index.html` 与 `demo/src/styles.css` 为模板，沿用深色左侧菜单、顶部标题、表单卡片和查询表格。主菜单为三个平级页面：**OCR识别**、**四性评分**、**规则查找**。其他业务模块全部移除。模型API配置通过顶部弹窗设置；规则维护位于规则查找页，JSON下载和来源追溯保留在相关页面。来源记录见 `docs/demo_template_source.json`。

## 五分钟重放

左侧“规则查找”是与“OCR识别”“四性评分”平级的独立页面，也可直接打开 `http://127.0.0.1:8765/#rules`。选择控制单后，上方搜索与四性/状态筛选，左侧表格每页10条，右侧显示选中规则全文、适用条件、来源及可展开的判断条件。窄屏改为上下排列，点击规则会滚动到详情。搜索支持空格分隔多个词并同时匹配，例如“型号 完整”；“清空筛选”恢复全部规则。OCR和评分页提供快捷入口，切换页面保留当前任务。规则JSON维护位于规则查找页底部；历史评分仍从评分明细查看当时依据。

1. 在“OCR识别”页保留编号 `DOC-A-0001`，点击“加载演示控制单”。
2. 在页码选择器中核对页图与纯文本；展开“识别结果与阶段JSON”，查看 `ocr.json`、`sections.json`、`rules-v1.json`、`ir-v1.json`、`dsl-v1.json`。
3. 点击“使用当前控制单进行四性评分”，切换“JSON批量物料”，加载50条合成物料，再点击“开始四性评分”。单条物料也可直接使用表单填写。
4. 表格显示五项数值分数。点击一条记录，再点击规则的“查看控制单/页码”，核对原文及页图。
5. 切换阶段、查找关键字或下载单个JSON；“下载全部JSON”打包本任务全部JSON。

**重放不是本次OCR/LLM调用。** OCR来自已保存的Codex视觉逐页识别；不冒称Qwen服务结果。13项DSL实际重新执行，完整性与身份唯一性使用明确的确定性合成参考库适配器。测试验证50条记录、650项规则结果、250个数值分数与已认可证据包一致。合成参考库的六个参数不代表真实厂家完整标准。

## 真实模型运行

在Demo顶部“模型API配置”分别填写视觉OCR、文本模型的API地址、密钥、模型名、超时、重试和最大输出token数，点击各自的连接检查。支持 **OpenAI兼容 Chat Completions**：URL填到 `/v1` 或完整 `/chat/completions`；视觉服务必须支持 `image_url` 内嵌PNG。无需认证的本地服务可留空密钥。

在“OCR识别”页选择“模型API识别”，输入控制单编号，选择PDF/图像后开始。软件实际按页发送视觉请求，得到**纯文本**，再封装JSON；OCR提示词常量原样复用。文本模型执行规则提取及逐条IR编译，程序构建DSL。原始模型输出、错误、规范化结果与引用章节/页码分别保存。完整性禁止模型评分；未知或未成功编译检查保留为待核实计0分。

模型输出仍需按原文审核。无证据不得生成工业事实，原文中只有示例的型号不能成为所有记录的固定要求。文本提取和编译提示词已按本次业务语义显式版本化，见 [PROMPTS.md](docs/PROMPTS.md)。

连接检查只验证一次真实请求能否返回；不证明模型提取准确性。当前未提供真实OCR/文本服务端点，真实供应商服务验收留待复现人员填写配置后执行。已通过的本地HTTP模拟服务测试与这项验收严格分开，见 [VALIDATION.md](docs/VALIDATION.md)。

## 规则维护和复评

“四性评分”页内的“当前控制单评分规则维护”支持加载并编辑规则JSON数组，新增、删除、停用、改描述/条件/权重/检查。`source_sections`必须存在；来源页码由章节重建。若改变规则语义，必须相应修改 `checks`，或设为 `[]` 让已配置文本模型重新编译。保存自动产生新规则版本和IR/DSL，**不会改写任何旧评分**。

物料编辑或导入同样不触发自动评分。每次手动评分保存输入快照、规则版本、规则明细、原因和数值分数。评分结果页可选择旧快照。模型编译失败的检查为 `UNKNOWN`，可继续人工修复或按待核实0分计入。

## 计分与证据

- 通过：1；失败或待核实：0。明确对象不同或运行时条件明确不适用：不进分母。
- 每性按适用DSL的 `rule_weight` 加权；没有适用规则时该性为0并记录原因。四性总分按 `dimension_weights` 加权，默认等权。
- JSON使用0–1、四位小数；Demo显示0–100。无“暂记0分”和双轨结果。
- 唯一性按控制单定义，身份确定性不等同于跨记录编码查重。当前通用运行模式不自动调用跨记录查重；此类规则需显式适配，未支持时计0并保留原因。
- 照片说明保留于OCR，但不进入四性规则和分母。完整性始终使用确定性检查。
- ML默认关闭，不附带或冒称存在训练产物。若已有模型服务，可显式配置 `ml` 证据桥接及权重；只计真实响应，错误证据计0，并保存模型版本、证据和状态。完整性禁止ML；唯一性ML必须声明身份确定性语义。原训练器不随包迁入，详见 [CONTRACTS.md](docs/CONTRACTS.md)。

## 文件与隐私边界

`runtime/<run_id>/` 存输入文件、页图和JSON阶段产物；整个runtime被Git忽略。API密钥只驻留内存，不写配置文件；日志不记录请求体，模型输出和导出内容会清理已配置密钥及敏感键。请不要在物料记录或原始文档中放入凭据。运行结果可能含用户主动输入的业务资料，应在共享前按实际数据范围审查。

仅复制已授权脱敏控制单、英文合成数据和必要的源模块。没有复制原配置、数据库、向量库、训练样本、模型、Excel上传后端或论文。来源哈希、复用与修复记录见 [SOURCE_AUDIT.md](docs/SOURCE_AUDIT.md)。

主要目录：`src/mqc_qcr` 软件、`static` Demo、`prompts` 版本化提示词、`samples` 脱敏测试样例、`vendor` 有来源记录的核心模块、`tests` 回归与HTTP契约测试、`docs` 审查材料、`scripts` 复现入口。

API契约可在运行中的 `/docs`、`/openapi.json`、`/api/schemas` 查询；离线契约在 [CONTRACTS.md](docs/CONTRACTS.md)。
